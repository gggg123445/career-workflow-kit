# 经历建档与定制简历

以 `profile.json` 和用户材料为事实依据。导入新简历时保留稳定经历 ID，把时间、贡献、指标来源和论文状态的冲突列明；能确认的字段先整理，重大冲突不要静默替换。文档解析依赖宿主工具，文本工具不可用时请求可读文本，不假装解析成功。

读目标 JD，把硬条件、工作职责和加分项分别映射到实际经历。输出“要求 → 经历 ID/证据 → 缺口 → 改写动作”。没有量化评分依据时不输出匹配度百分比，更不能当成录取概率。

改写保持“做了什么、为什么这样做、如何验证、结果是什么”的因果关系。指标缺失时保留可验证的功能结果或标注待补；不要求每一句都有数字。按实际贡献选择参与/负责/设计/主导。论文的在投、在审、录用、发表保持原状态。

交付简历正文、关键改动与待补清单。按目标岗位调整经历顺序，但不自动删除用户看重的方向。版本关联同一投递记录；更换岗位重新准备任务，保留旧版。

`render resume --output <新文件.md>` 可从档案排出事实草稿，不会自动匹配 JD。要生成正式投递稿，继续做上述内容工作。PDF/Word 可用宿主工具导出并检查分页、字体和联系方式；没有工具时交付 Markdown，不声称已生成其他格式。

验收：每个数字和强结论有来源；项目名称与档案一致；联系方式和日期无占位；JD 中未具备的能力没有通过关键词堆砌变成“已掌握”。
