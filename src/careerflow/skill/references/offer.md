# Offer 条款与取舍

记录原始条款、币种、计价周期、发薪月数、试用期、奖金是否保证、签字费返还条件、权益归属与工作安排。缺失值与用户已确认的零值分开。先做可比口径，再结合偏好判断。

现金分为保证现金、条件性现金、一次性现金；股权/期权单列归属与流动性风险，不能按估值比例随意折算成可兑现现金。月薪乘发薪月数已经包含的奖金不再加一次。首年与稳定年度分开，明确每项假设。

可以使用 `offer-calc <文件.json>` 计算用户已提供的税前现金条目。它不计算税后、社保、政策补贴、股票价格或概率，也不替用户填入任何默认市场参数。以下是输入结构示例，数字仅为演示，所有现金字段必填，零代表已确认没有该项；未知时先补齐资料，不填零代替未知：

```json
{
  "currency": "CNY",
  "monthly_base": "10000",
  "guaranteed_months": "12",
  "guaranteed_annual_allowance": "0",
  "conditional_bonus": "10000",
  "first_year_signing_bonus": "5000"
}
```

在技能目录执行 `python scripts/careerflow.py offer-calc <文件.json>`；更多参数见 `offer-calc --help`。

税率、缴费基数、政策资格和法律条款如影响结论，用宿主可用能力核验当期官方来源并标注日期；核验不到时保留待核实，不套用过期默认值。不要把无法立即支取的社保或公积金直接称为当期可支配现金。

比较团队、职责、成长、稳定、工作节奏、城市和现金约束。用户没有确定权重时先列取舍，不默认一个综合分决定去向。有评分时说明依据，并试着调整关键权重，看排序是否稳定；相近评分只能说明对假设敏感，不能称为统计显著或不显著。

交付每份 Offer 的口径表、缺口、重要合同条件，以及不同偏好下的选择理由。谈薪只能引用真实 Offer 或可核实市场信息，不编造竞争方案。最终取舍由用户决定。
