# 架构与扩展契约

## 同一核心，两种入口

```text
人工 / 任意 Agent                支持技能目录的宿主
      │                             │
      │ CLI                         │ SKILL.md → 当前阶段 reference
      └───────────┬─────────────────┘
                  │ careerflow Python 标准库运行时
                  ▼
      本地工作区 / JSON、Markdown、EML、CSV、ICS、HTML
```

CLI 与 Skill 使用相同函数。动态加载接口为 `skills.catalog()`、`skills.load(stage=None)`；CLI 对应 `skill catalog`、`skill load [stage]`。加载入口不会加载七份正文；宿主选择当前阶段再读。`agents/openai.yaml` 只提供可选 UI 元数据，不是运行时依赖。

## 数据层

| 路径 | 责任 |
|---|---|
| `profile.json` | 用户提供的经历事实 |
| `targets.json` | 城市、方向等偏好 |
| `applications.json` | `schema_version`、递增 `revision`、岗位、阶段任务与事件历史 |
| `inputs/` | 用户材料及离线邮件 |
| `runs/<id>/` | 任务快照和可交接的提示词 |
| `artifacts/` | 登记文件的副本与 SHA-256 引用 |
| `exports/` | 演示或用户自行安排的导出文件 |

岗位 ID 不从公司名推导，因此同一公司多个岗位独立。阶段任务可以多次执行；`plan` 展示每阶段最新登记状态，旧版本仍保留。更新台账先在副本上修改，再在锁内原子替换；重复无变化更新不增加版本。锁避免多个本项目进程同时写入，不是通用数据库或跨主机分布式锁。

`prepared` 表示任务已准备，`completed` 表示产物已登记并附核对说明。产物专业质量、来源真实性、外部操作结果须由执行者另行核验。`verify` 仅检查引用完整性和哈希。

## 时间和导出

原始时间字段保留人可读文本和显式固定 UTC 偏移；导出 ICS 时转为 UTC。没有地理时区规则数据库，夏令时地区应对每个日期提供正确偏移。无效日期、结束早于开始、重复时段或混入未识别文本均拒绝整次写入。

ICS UID 由岗位 ID、轮次和时间槽序号构成。修改原槽时间可保持 UID；改变槽顺序会改变事件对应关系。导出不连接日历，也不保证第三方客户端合并或删除行为。CSV 对可能触发表格公式的单元格加前置单引号。

## 外部适配器

核心不包含账号、联网客户端、模型 SDK 或平台资源 ID。若新增飞书 / Notion / 邮箱适配器，使用本地 ID 建立显式映射，并记录来源版本与执行结果；不要把公司名当唯一键，也不要将导出成功称作同步成功。云端与本地发生冲突时展示差异，再按用户选择解决。

敏感配置和外部写入由适配器负责，能力应可独立关闭。不要把个人 token、记录 ID 或真实样本写入通用模板。模板契约位于 `resources/campus-tracker.json`，只携带字段与状态语义。

## 发行

Python wheel 包含运行时、通用模板、Skill 入口与资料。`skill install` 从当前版本生成完整新目录，捆绑同版本运行时；发布 ZIP 使用相同安装函数构建，避免独立维护两份业务代码。源码 Skill 目录中的 launcher 可在源码树里运行，但单独复制该目录不构成完整发行包。

新版本安装到新目录，再按宿主方式切换，避免覆盖用户修改。工作区不嵌入技能目录，升级技能不会迁移个人数据；跨 schema 版本变更需单独定义迁移。
